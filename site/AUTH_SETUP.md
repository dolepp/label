# Вход по почте, Google и Яндексу

Регистрация по почте происходит после подтверждения восьмизначного кода из письма. Пароль не нужен. Код действует 10 минут, используется один раз и допускает не более пяти ошибок. Не больше пяти писем на один адрес в час; повторная отправка доступна через минуту.

## Настройки сервера

Секреты храните в `/root/work/label/.env`, который читают API и бот. Примеры имён переменных приведены в `.env.example`. После изменения перезапустите `twaslabel-api.service`. До настройки провайдера его кнопка отключена; `/api/auth/options` показывает доступные способы входа без секретов.

Google: создайте OAuth-клиент типа **Web application** и задайте `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`. Разрешённый redirect URI:

```
https://api.twaslabel.ru:8443/api/auth/oauth/google/callback
```

Яндекс: зарегистрируйте приложение Яндекс OAuth, разрешите `login:info` и `login:email`, задайте `YANDEX_CLIENT_ID`, `YANDEX_CLIENT_SECRET`. Redirect URI:

```
https://api.twaslabel.ru:8443/api/auth/oauth/yandex/callback
```

Для почты заполните `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURITY`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM`. Поддерживаются `starttls` (обычно 587) и `ssl` (обычно 465). Сертификат SMTP проверяется. Адрес отправителя должен быть разрешён вашим почтовым сервисом. В продакшене нужны корректные SPF/DKIM согласно требованиям выбранного SMTP-сервиса.

`AUTH_FRONTEND_URL` по умолчанию `https://twaslabel.ru`, `AUTH_API_URL` — `https://api.twaslabel.ru:8443`. У обоих должен быть действующий HTTPS-сертификат. При изменении адресов обновите redirect URI у провайдеров и CORS API.

Документация: [Google OAuth](https://developers.google.com/identity/protocols/oauth2/web-server), [Яндекс OAuth](https://yandex.ru/dev/id/doc/ru/codes/code-url).

## Профиль и Telegram

В профиле доступны подтверждение почты и привязка Google/Яндекса к уже открытому аккаунту. Совпадение контактного email не объединяет аккаунты: email в редактируемом профиле не является подтверждённым способом входа. Если входите через OAuth и хотите также входить по почте, сначала подтвердите почту в этом профиле.

Для нового веб-аккаунта нажмите «Привязать Telegram», откройте полученную ссылку в боте, нажмите «Старт» и затем «Проверить привязку» на сайте. Ссылка действует 10 минут и используется один раз. Привязанный Telegram также позволяет войти через команду `/код`; бот открывает тот же профиль. Для обычного `/start` у привязанного веб-аккаунта бот показывает ссылку на сайт вместо создания второго профиля.

Если Telegram уже имеет другой профиль, привязка отклоняется без переноса баланса или релизов. Войдите через Telegram в существующий профиль и добавьте другие способы входа там. Автоматического объединения готовых аккаунтов нет.

Уведомления о релизах, договорах и отчётах используют привязанный чат. В профиле их можно отключить; у веб-аккаунта Telegram можно отвязать. У существующего Telegram-аккаунта отключаются уведомления, но сохраняется способ входа. Для новых веб-аккаунтов все действия выполняются в кабинете; Telegram служит для уведомлений и получения кода входа.

## Миграция и проверка

До обновления API/бота примените `migrations/005_multi_provider_auth.sql` к общей PostgreSQL-базе. Миграция добавляет таблицы идентификаций и подтверждений, а также настройки уведомлений. Идентификаторы существующих пользователей, релизов, платежей и файлов сохраняются; новые веб-аккаунты получают отрицательный постоянный ID в legacy-поле `label.telegram_id`, API отдельно возвращает `account_id` и реальный `telegram_id`.

Интеграционные тесты `site/tests/test_account_auth.py` работают в отдельной временной схеме PostgreSQL и удаляют её после выполнения. Они требуют `TEST_AUTH_POSTGRES=1` и переменные `POSTGRES_*`; отправка почты и запросы OAuth подменяются тестовыми ответами. Команда: `python -m unittest discover -s site/tests`.
